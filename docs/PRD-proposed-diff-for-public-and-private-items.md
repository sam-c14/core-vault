The repository architecture strictly divides the mathematically verifiable accounting engine (public) from the commercially viable market features and network integrations (private).
* Public Repository ([github.com/your-org/corevault](https://github.com/your-org/corevault))This repository operates under an OSI-approved license (Apache 2.0 or MIT) and contains the foundational banking primitives. It serves as the trusted, auditable core that developers can clone and run locally.crates/core-types: The data structures for currency precision (rust_decimal), basic account invariants, and standard transaction states.crates/double-entry-engine: The immutable ledger logic that strictly enforces $\sum \text{Debits} = \sum \text{Credits}$ before any transaction is committed to the database.crates/nuban-validator: The open-source mod-10 check-digit algorithm used for generating and validating basic NUBAN formats.crates/account-manager: The state machine handling standard account lifecycles (Pending, Active, Frozen, Post-No-Debit) and row-level database locking.crates/transaction-api: The base REST and gRPC endpoints for initiating standard internal transfers and checking balances, including the Valkey idempotency locks.crates/platform-config-parser: The engine that reads and applies the declarative TOML rules for localization, without containing the proprietary regulatory data itself.Private 

* Repository ([github.com/your-org/corevault-enterprise](https://github.com/your-org/corevault-enterprise))This closed-source repository imports the public CoreVault crates as standard Cargo dependencies. It contains the proprietary business logic, Nigerian-specific switch integrations, and the advanced consumer features required to monetize the platform.crates/nibss-gateway: The proprietary TCP/HTTP connector for NIBSS Instant Payments (NIP), including inward/outward settlement pipelines and Name Enquiry API endpoints.crates/escrow-engine: The state machine managing the P2P buyer/vendor holding accounts, OTP cryptographic handshakes, and third-party logistics webhook listeners.crates/delayed-settlement: The delayed-job queue manager that powers the "Undo Transfer" feature, temporarily holding funds in a PENDING_OUTBOX state before releasing them to NIBSS.crates/smart-tags: The intelligence layer handling deterministic merchant binding, automatic rule-based NUBAN routing, and the "Runway" calculation analytics.crates/compliance-cbn: The automated reporting service that formats and encrypts the mandatory XML files for the Nigerian Financial Intelligence Unit (NFIU) and CBN.crates/dispute-resolution: The automated chargeback logger that packages Retrieval Reference Numbers (RRN) and pushes them to the NIBSS Arbitration API for POS dispense errors.
